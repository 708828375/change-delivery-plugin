# 阶段 Skill 提示词优化

## 背景

插件的 12 个阶段 Skill 已能覆盖固定交付流程，但提示词逐步积累了大量步骤、禁令和重复 Schema。运行主机本身已经注入状态策略、输出 Schema、允许动作与禁止动作，继续在 Skill 中重复这些内容会挤占模型注意力，也使个性化修改更难定位。

本次参考《Harness Engineering：比提示词工程更重要的下一站》中的思路，保留模型无法自行推断的交付契约，把可执行的硬约束交给运行主机、Schema 和测试。

## 调整

- 12 个 `SKILL.md` 统一围绕阶段目标、完成或退出判据、证据和权限边界编写。
- 删除重复的 `StageResult` Schema、状态映射、动作白名单和教程式步骤。
- `references/` 只保留团队约定、ExampleProject 异步风险、SHA 连续性、验收资源台账等专项知识，并明确按条件加载。
- 将测试从大量固定句子断言改为阶段语义契约、专项引用路由和注意力预算检查。
- README 补充 Skill 与运行主机的内容分工原则。

## 结果

- 12 个 Skill 正文总字符数从约 12,207 降至 5,942。
- 否定式指令标记从约 120 个降至 1 个。
- 状态机、阶段路由和副作用实现未改动。
- Plugin validator、关键兼容测试和 899 项全量测试通过。

本次只更新插件源码，未自动覆盖用户已安装的发布副本。
