# 插件共享版本改造

## 背景

Change Delivery 原先绑定单一 Windows 用户、固定 Python/Codex/GitHub CLI 路径和源码 clone，无法直接分发给其他 Codex CLI 用户。个人安装器还会让 Codex 读取完整开发仓库，曾触发测试缓存目录“拒绝访问”。

## 主要修改

- 将可安装 Plugin 收敛到 `plugin/change-delivery-plugin`，Marketplace 只读取 manifest 与六个技能，不递归运行时、测试或 Git 元数据。
- 新增共享布局、运行时发布、共享安装和安全卸载脚本；路径统一由 Windows Known Folder 推导。
- 为每个用户创建专用 Python venv、已安装 host 和稳定 launcher，运行不再依赖 clone。
- 计划任务固定已安装 host，安装时发现并验证唯一的 Codex/GitHub CLI，运行时使用绝对路径和 SHA-256。
- 版本统一为 `0.2.0`，Git Marketplace 注册固定 `708828375/change-delivery-plugin@v0.2.0`。
- Marketplace 更新前创建受控本地快照；远端注册或 Plugin 安装失败时恢复旧 Marketplace。
- `runtime-host.json` 作为可重建控制状态支持已验证计划任务下的原子轮换，默认卸载会安全删除；`projects`、`runs`、`logs`、`state` 默认保留。
- 卸载计划任务前重建并比较完整任务定义，拒绝多 Action、参数子串、principal、trigger 或 settings 不一致的同名任务。

## 兼容性与边界

- 支持 Windows PowerShell 5.1、Python 3.12+ 和 Codex CLI。
- 私有团队分发阶段继续使用 `UNLICENSED`。
- 共享安装不读取或复制 token、密码、SSH key、Codex 登录内容或项目注册数据。
- host、venv、launcher 和技能目录分别原子切换；已验证并完成的阶段在后续失败时保留新版本，安装器可幂等重跑。Marketplace 切换具有旧快照回滚。
- 自动 tick 继续走已安装 host 的哈希锚定 `run-tick.ps1`；交互技能统一走稳定 launcher。

## Review 结果

独立审查未发现 Critical，提出 5 个 Important，均在最终验证前处理：

1. 同步 Python 模块清单、模块清单哈希与两个 host-security 嵌入哈希，并增加仓库实树一致性测试。
2. 增加 `runtime-host.json` 原子升级和默认卸载清理。
3. 安装器与卸载器复用官方 Codex npm package graph 校验，不再执行 PATH 中未验证的 shim。
4. 卸载计划任务由参数子串判断升级为完整定义比较。
5. README 补齐 `api_key`/`auth_file` 参数，并将规格修正为计划任务执行已安装 host。

Marketplace 跨阶段回滚额外增加旧 Plugin 白名单快照；本地组件采用逐阶段原子切换与幂等续装，而不是持有整个 venv 的跨阶段副本。

## 验证结果

- `python -m pytest -p no:cacheprovider -q`：845 项全部通过。
- `python -m compileall -q src`：通过，随后清理生成的 `__pycache__`。
- 官方 Plugin validator：通过。
- 官方 Skill quick validator：六个技能全部通过；Windows 下设置 `PYTHONUTF8=1`。
- 隔离 `CODEX_HOME` 实装：Marketplace 注册成功，`change-delivery-plugin@joysun-team` 安装成功，版本 `0.2.0`，插件源为独立白名单树。
- 本机 Codex/GitHub CLI 身份发现：验证通过，计划任务可记录原生可执行文件和哈希。
- 分发内容个人路径、凭据模式、缓存/bytecode 扫描与 `git diff --check`：通过。
