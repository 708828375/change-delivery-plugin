# 插件发布目录安装修复设计

## 背景与根因

个人 Marketplace 将 `change-delivery-plugin` 的源码路径配置为
`C:\Users\ExampleUser\plugins\change-delivery-plugin`。现有安装脚本把该路径创建为指向开发仓库根目录的 Junction。

Codex CLI 0.146.0 安装本地插件时会递归复制 Marketplace 条目指向的整个目录。开发仓库包含 `.git`、测试输出和由不同沙箱身份创建的临时目录；其中部分目录不可读，因此 Codex 在复制过程中以 `os error 5` 失败。

## 目标

- Marketplace 源目录只包含 Codex Plugin 运行所需的文件。
- 首次安装和重复安装均可安全收敛到同一目录结构。
- 不修改现有个人 Marketplace 文件。
- 不依赖开发仓库中的 Junction、测试产物或 Git 元数据。
- 在调用 `codex plugin add` 之前完成发布目录校验。

## 非目标

- 不改变 Python 编排器的安装方式；它继续由现有 editable Python package 提供。
- 不改变插件技能内容、状态机、计划任务或生产发布规则。
- 不清理开发仓库中已有的测试临时目录。

## 方案

安装脚本将 `C:\Users\ExampleUser\plugins\change-delivery-plugin` 管理为普通目录，而不是 Junction。发布内容采用显式白名单，仅包含：

- `.codex-plugin/`
- `skills/`

脚本先在固定 Plugins 根目录下创建同文件系统的临时发布目录，将白名单内容复制进去，并使用官方校验器验证临时目录。验证成功后，脚本再替换最终发布目录，最后调用：

```text
codex plugin add change-delivery-plugin@codex-marketplace-global
```

开发仓库仍是事实源；每次运行安装脚本都会重新生成干净发布副本。

## 安全与失败处理

- 固定校验当前用户目录和 `C:\Users\ExampleUser\plugins` 信任锚。
- 源目录必须是普通目录，且包含有效插件清单和技能目录。
- 临时目录及最终目录必须位于已校验的固定 Plugins 根目录下。
- 最终目录若是现有 Junction，仅在确认它恰好是预期插件路径且目标为当前源码后移除 Junction 本身，不递归删除其目标。
- 最终目录若是普通目录，只允许替换安装器自己管理、且能通过插件结构校验的目录；意外文件或其他链接类型一律失败关闭。
- 先完成临时副本及校验，再切换最终目录，避免把半成品暴露给 Marketplace。
- `codex plugin add` 失败时保留已验证的发布目录，便于诊断和重试；不修改 Marketplace 配置。

## 数据流

```text
开发仓库
  ├─ .codex-plugin ─┐
  └─ skills ────────┴─> 临时发布目录 ─> 官方校验 ─> 普通最终目录 ─> Codex 插件缓存
```

Python 编排器继续从当前 editable package 加载，不从 Codex 插件缓存加载。

## 测试策略

- 回归测试确认安装器不再创建或要求最终插件目录为 Junction。
- 测试确认发布白名单只包含 `.codex-plugin` 与 `skills`。
- 使用临时目录验证首次发布和从预期 Junction 迁移为普通目录的行为。
- 验证异常普通目录、错误 Junction、重解析点和复制失败均在调用 Codex 前失败关闭。
- 解析全部 PowerShell 脚本，并运行相关安装安全测试。
- 在真实个人目录上最终验证 `codex plugin add` 成功，并确认插件出现在 `codex plugin list --json` 中。

## 验收标准

- `C:\Users\ExampleUser\plugins\change-delivery-plugin` 是普通目录。
- 该目录顶层只包含 `.codex-plugin` 和 `skills`。
- `codex plugin add change-delivery-plugin@codex-marketplace-global` 返回成功。
- `codex plugin list --json` 显示插件已安装。
- 重新运行安装脚本能够安全、确定性地更新插件发布副本。
