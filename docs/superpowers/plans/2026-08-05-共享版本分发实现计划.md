# Change Delivery Plugin 共享版本分发实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 将绑定单一 Windows 用户和源码目录的插件改造成可由不同用户通过私有 Git 仓库安全安装、升级和运行的共享版本。

**架构：** 安装器从 Windows Known Folder 推导用户根目录，把技能插件、专用 Python venv、受信任运行主机和稳定启动器分别发布到用户目录下。技能与计划任务只调用稳定启动器；团队 Marketplace 固定引用 Git tag，用户数据不进入仓库或发布树。

**技术栈：** PowerShell 5.1、Python 3.12、pytest、Codex Plugin CLI、GitHub/Git Marketplace。

---

## 文件结构决策

- 创建 `scripts/shared-layout.ps1`：唯一负责用户目录校验、共享安装路径推导和普通目录检查。
- 创建 `scripts/runtime-publisher.ps1`：唯一负责 venv、host、launcher 的 staging、验证、原子切换和回滚。
- 创建 `scripts/install-shared-plugin.ps1`：共享安装编排入口。
- 修改 `scripts/install-personal-plugin.ps1`：保留兼容入口，转调共享安装器。
- 修改 `scripts/plugin-publisher.ps1`：插件发布仍只包含 manifest 与 skills，不混入 Python 运行时。
- 修改 `scripts/install-scheduled-task.ps1`、`scripts/run-tick.ps1`、`scripts/host-security.ps1`：信任已安装 host 和专用 venv，不信任 clone 路径。
- 创建 `scripts/uninstall-shared-plugin.ps1`：默认保留项目与 run 数据的受控卸载。
- 创建 `.agents/plugins/marketplace.json`：Git-backed 团队 Marketplace，指向独立的 `plugin/change-delivery-plugin` 白名单树。
- 修改六个 `skills/*/SKILL.md`：所有编排 CLI 调用经稳定启动器执行。
- 移动 `.codex-plugin/plugin.json` 与 `skills` 到 `plugin/change-delivery-plugin`，并与 `pyproject.toml` 统一为 `0.2.0`。
- 创建 `README.md`：团队安装、升级、调用、诊断、卸载和认证说明。
- 新增/修改 `tests/unit/test_shared_*.py` 与现有安装测试：覆盖可移植性、安全边界、发布回滚、技能入口和版本一致性。
- 创建 `docs/开发记录/2026-08-05-插件共享版本改造.md`：记录实现与验证结果。
