# Delivery Planning

Read `requirement.md` completely. Inspect repository context only when it is
available inside the permitted work directory.

Write only `design.md` and `implementation-plan.md`. Make requirements,
success criteria, affected components, risks, test strategy, rollback, and
ordered implementation tasks explicit. Record unresolved product or
architecture decisions instead of guessing.

Do not edit product code. Do not approve the design, commit, push, deploy,
merge, run network writes, or expand the requested scope. Return the
host-requested structured stage result and cite the two written artifacts as
evidence.
