# 项目分析与测试策略

本文件只补充交付流程需要提前固定的决策，不替代仓库自身文档。

## 设计必须回答的问题

- 行为从哪个真实入口开始，经过哪些状态或异步边界，最终由什么可观察结果证明完成？
- 哪些现有接口、Service、Repository、DTO、状态枚举或测试夹具应复用？
- 兼容性、迁移、回滚或停止条件是什么？哪些未知项必须由人确认？

## 验收策略

- 每条成功标准绑定一种证据层级：单元/集成测试、接口 E2E、测试环境验收或人工专项检查。
- 真实网页、AI 判断、第三方最终结果、真实邮件收件和人工支付不作为稳定主门禁；需要时使用沙箱、mock、本地替身或明确人工步骤。
- 异步链路说明任务入口、终态、最大等待边界和日志/数据证据，不能以“已入队”代替完成。
- 临时数据需要运行标记、资源台账、精确清理和清理失败处理；默认通过公开接口准备。

`design.md` 与 `implementation-plan.md` 只纳入批准需求所需工作，并明确残留风险与无法自动覆盖的场景。
