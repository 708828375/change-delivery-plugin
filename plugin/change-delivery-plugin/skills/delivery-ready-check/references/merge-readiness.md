# 合并就绪补充检查

## 证据一致性

- 本地验证、内部 Review、测试分支、测试环境验收、CI 和外部 Review 必须绑定当前同一 SHA。
- 历史通过、旧 PR head、计划执行或人工口头说明不能代替当前证据。
- Review 修复后应存在对应的重新验证和新树 Review，不得沿用修复前结论。

## 交付完整性

- 项目要求开发记录或架构决策时，检查相关文档已纳入当前变更，并忠实记录背景、取舍、影响、验证和残留风险。
- 检查迁移、配置、兼容、部署注意事项和回滚要求已进入 PR 内容或项目约定文档。
- 测试环境临时资源应有准确资源清理证据；未清理项必须说明原因、影响和后续责任人，不能静默忽略。

## 结论

缺失必需证据、仍有可执行 Review 问题、资源清理不完整或风险需要人工决策时返回 `blocked`。Skill 只给出补充判断，不能修改门禁，也不能把自己的结论当作 `READY_TO_MERGE`。
