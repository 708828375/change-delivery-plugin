# 团队 Review 判据

先核对批准范围和兼容性，再检查正确性、安全、数据一致性、并发、性能与真实测试缺口。格式或替代写法不应掩盖行为风险。

## 分级

- **必须修复**：安全漏洞、数据丢失、重复扣费、逻辑错误、恢复失败、任务卡死、资源耗尽或确定性测试缺口，映射为 `critical` 或 `important`。
- **建议修改**：当前可运行，但会明显放大负载、降低恢复能力或持续增加维护风险；按当前门禁决定是否映射为 `important`。
- **仅供参考**：命名、等价写法或未来规模优化，映射为 `minor`，不阻塞通过。

每条 finding 必须能定位代码，说明触发条件、实际影响和建议方向。无法从当前树证明的问题不作为缺陷。

## 退出判据

高风险路径已覆盖且 findings 已完整列出；存在“必须修复”或被门禁认定为阻塞的“建议修改”时不通过，只有“仅供参考”不阻塞。
