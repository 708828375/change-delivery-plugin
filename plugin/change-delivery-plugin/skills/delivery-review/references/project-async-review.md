# ExampleProject 异步任务专项 Review

仅当变更涉及相应链路时应用。

## Outbox、任务与幂等

- Outbox payload 与 Celery task 参数必须兼容；派发崩溃窗口不能造成重复数据、重复扣费或永久阻塞。
- 幂等键表达稳定业务身份或真实处理轮次，不得使用随机值掩盖合法重试问题。
- 成功结果落库与 item 终态之间的事务缝隙必须存在带状态和锁守卫的补偿路径。

## 并发、锁与恢复

- 多个并发 worker 不得共享同一个 `AsyncSession` 执行查询或提交。
- 状态更新检查当前状态、锁归属和软删条件，不能把 `FAILED`、`SKIPPED` 或他人持有的 `RUNNING` 无条件改成成功。
- Watchdog、锁过期和心跳续租必须受业务绝对超时约束；可自动恢复的工作不能依赖人工重新启动。

## 扣费与实时状态

- 已成功处理的 item 重跑不得重复扣费；已扣费后失败应能通过幂等证据识别。
- WebSocket 快照、订阅和重连之间不得静默漏失关键状态；畸形消息和慢消费者不能拖垮共享连接资源。

## 大表扫描

- 周期性查询先列出 `WHERE`、`ORDER BY`、`GROUP BY` 和 `LIMIT`，确认索引前缀与查询条件匹配。
- 对分区表和 partial index 以迁移及实际数据库结构为准，不能仅凭 ORM 声明判断生产索引存在。
