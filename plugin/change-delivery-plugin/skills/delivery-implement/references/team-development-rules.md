# 团队开发规则

## 项目约定

- 延续仓库已有分层、依赖方向、事务、缓存、日志、配置与测试夹具；新增平行能力前先确认现有结构无法承载。
- 数据库变更为新表补充表注释，为新增业务字段补充字段注释；索引、唯一约束和状态字段应体现业务含义。
- 批量链路说明查询次数、分页或批处理边界、锁、幂等与失败隔离，避免把 N+1 或无界加载带入主路径。

## 中文与记录

- 新增日志、错误提示、代码注释和开发文档优先使用自然中文；变量、类型、接口、命令和错误码保留英文。中文文件使用 UTF-8。
- 项目已有开发记录或架构决策目录时，按既有方式更新开发记录，包含背景、主要修改、复用与取舍、影响范围、实际验证和残留风险；没有现成约定时不新建文档体系。

无关重构、全局格式化、目录迁移和依赖升级不进入本次实现。
