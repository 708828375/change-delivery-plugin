# 测试资产实现规则

仅当已批准计划包含接口测试集合、mock、seed、cleanup 或异步测试编排时应用本文件。

## 变量契约

- 每个测试变量都必须有发生在使用之前的来源，例如环境初始值、前序响应、预置脚本输出或明确人工步骤。
- 创建请求保存后续需要的准确主键；轮询保存 job 或 task ID，并设置有界重试和明确终态。
- 字段路径以 DTO、响应模型或实际响应为准，不能猜测 `data.id`、`access_token` 等路径。

## 外部依赖和 mock

- 每个外部依赖明确选择 mock、真实沙箱、本地替身或人工步骤，不混用旧 mock 和真实配置。
- mock 必须核对方法、路径、query、header 和 body，并通过已批准的最小请求证明能够命中。
- 依赖 AI、真实搜索、真实网页、真实邮箱或人工支付的结果不得成为稳定数量断言。

## seed 与清理

- 优先通过公开接口创建数据。只有公开接口无法建立必要状态且方案已批准时，才编写 seed。
- seed 必须幂等、有准确测试标记、输出所需 ID，并覆盖代码真实读取的存储路径。
- 清理必须限定到本次运行记录的准确资源，支持预演或明确命中范围；不得按空前缀、宽泛时间范围、共享账户或猜测 ID 删除。

测试资产只能服务已批准场景，不得为了让断言通过而修改生产业务状态机或增加测试专用业务分支。
