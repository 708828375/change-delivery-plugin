# ExampleProject 功能验收补充规则

## 场景执行

- 优先从 public API、前端入口或已批准的 WebSocket 探针验证用户可见行为。
- 每个场景明确前置状态、操作、确定性断言、异步等待上限、资源 ID 和清理动作。
- API 接受或返回 request ID 只证明请求进入链路，不能替代任务终态、业务结果或接收端证据。

## 环境事实

- 执行前后持续核对远程测试分支和版本端点的预期 SHA；版本变化立即停止。
- 仅当运行主机已经提供相应只读探针事实时，才核对 Docker 日志、容器状态、Outbox、worker、WebSocket 状态和只读 SQL 结果。
- Skill 不自行建立 SSH 或数据库连接，不使用个人密钥路径，也不把模型叙述当作日志或数据库证据。

## 数据和外部依赖

- 临时数据通过已批准 public API 创建，并以运行编号或准确前缀标记；记录每个资源的类型和 ID。
- 不直接写数据库准备状态。确实需要 DB setup 时返回 `blocked`，交由流程外的单独授权操作处理。
- 不发送真实邮件、不支付、不调用生产计费服务；依赖真实外部系统时只断言可重复且有权威证据的部分。

## 完成条件

验收报告必须列出已通过场景、失败或阻塞场景、未覆盖项、清理结果和残留风险。资源清理不完整、环境 SHA 不确定、日志或只读 SQL 事实缺失时，不得返回 `passed`。
